# WindowsMonitor 八小时案例研究

研究窗口从 2026-11-01 01:05 UTC 到 09:05 UTC。先完成准备轮；此后每小时查询一次，共八次。时间以 UTC 为准，避免洛杉矶当天夏令时切换造成重复。

## 准备轮

已核查三类证据，并为相应检测编写无害回归样例。

- Adrozek 能改写浏览器扩展和启动配置。对 Chrome、Edge 默认位置中的用户配置建立基线，区分版本升级与同一版本目录中的文件变化。[微软案例，2020-12-10](https://www.microsoft.com/en-us/security/blog/2020/12/10/widespread-malware-campaign-seeks-to-silently-inject-ads-into-search-results-affects-multiple-browsers/)
- 受控文件夹访问和攻击面缩减有不同的审计与阻止事件。报告依据事件号分别展示实际处置，并显示当前防护模式。[微软事件定义](https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-windows-events)
- Phobos 曾使用系统工具删除卷影副本或关闭启动恢复。检查已注册任务中直接调用这些工具的动作，保留原始参数和任务启用状态。[CISA 等机构联合通告，2024-02](https://www.cisa.gov/sites/default/files/2024-02/aa24-060a-stopransomware-phobos-ransomware_1.pdf)

## 每小时执行

1. 核对当前 UTC 时间、上一轮来源、已发布版本和运行中的采集范围。
2. 从微软、CISA、CERT 或原始研究机构查证一个具体案例，记录原始发布日期和能在 Windows 上观察到的行为。优先处理新的证据、现有盲区和实际误报。
3. 对照实现和已有测试。只有能复现并验证改进效果时修改代码，用临时配置、合成事件或只读本机采集验证。没有可行动变化时记录依据。
4. 如果改版，测试独立 EXE、运行回归，按发布脚本提交并推送，核对远端提交。报告覆盖缺口和部署状态。
5. 在本机研究记录中记下轮次、实际查询时间、来源、结论及版本。第八小时结束后汇总实际执行记录，结束这次小时计划。

本机设置、数据库和原始报告保存在版本库之外。
